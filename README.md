# Reality Check — Feasibility Pre-Mortem

A full-stack app that gives founders and creators a rapid, honest feasibility
teardown of a business idea, invention, or creative project — before they
spend meaningful time or money on it.

Describe your idea in one paragraph and get back a structured pre-mortem:
similar products already on the market, the most likely ways the idea fails,
the single riskiest assumption it depends on, and three cheap experiments to
run before committing real money.

## Features

- **One-paragraph input** — describe the idea in plain language, no forms.
- **Structured teardown**, generated by Claude, with exactly six sections:
  1. What You're Actually Building
  2. Who's Already Doing This
  3. Why This Might Fail
  4. The One Assumption Everything Depends On
  5. Three Validating Experiments (Do These Before Spending Real Money)
  6. Verdict
- **Direct, specific tone** — the assistant is instructed to be blunt and
  concrete rather than encouraging, and to say "don't build this" when that's
  the honest read.
- Example ideas you can load with one click to see the format before writing
  your own.

## Architecture

```
server/   Express API that calls the Anthropic Messages API with a fixed
          system prompt and returns the model's teardown as markdown
client/   React + TypeScript SPA (Vite) that collects the idea and renders
          the teardown, calling the API via /api/* (proxied in dev)
```

### Backend (`server/`)

- `src/config/systemPrompt.js` — the fixed system prompt defining the
  feasibility-checker persona, the six required sections, and the tone rules.
- `src/routes/teardown.js` — `POST /api/teardown` — validates the idea text,
  calls the Anthropic Messages API (model configurable via
  `ANTHROPIC_MODEL`, default `claude-sonnet-5`), and returns
  `{ teardown: string }` (markdown).
- `src/loadEnv.js` — loads `server/.env` if present, without adding a
  dependency.

### Frontend (`client/`)

A single page: a textarea for the idea, a submit button, and the rendered
teardown (via `react-markdown`) once the API responds. Loading and error
states are handled inline.

## Running locally

1. Get an API key from the [Anthropic Console](https://console.anthropic.com/)
   and put it in `server/.env`:

   ```bash
   cd server
   cp .env.example .env
   # edit .env and set ANTHROPIC_API_KEY=sk-ant-...
   ```

2. Start the API server (`http://localhost:4000`):

   ```bash
   cd server
   npm install
   npm run dev
   ```

3. Start the web app (`http://localhost:5173`):

   ```bash
   cd client
   npm install
   npm run dev
   ```

The Vite dev server proxies `/api/*` to `http://localhost:4000`, so just open
`http://localhost:5173`.

## Notes

- The app has no database — every request is a single call to the Anthropic
  API with the idea text as the user message.
- If `ANTHROPIC_API_KEY` isn't set, the server returns a clear error instead
  of failing silently.
- `server/.env` is git-ignored; only `server/.env.example` is committed.
